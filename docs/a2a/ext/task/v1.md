# A2A extension: task/v1

- **URI:** `https://madarauchiha-314.github.io/rusty-harness/a2a/ext/task/v1`
- **Schema:** [`v1.schema.json`](./v1.schema.json) (JSON Schema, generated from the Rust
  types and contract-tested against `specs/a2a-ext/task.v1.schema.json`)
- **Rides on:** `Task.metadata`, the first `Message.metadata`, `TaskStatus.message.metadata`

## What it carries

The task record as the harness sees it: its name, type, goal, description and acceptance criteria,
whether it is `one-shot` or `long-running`, its sub-tasks, parents and the finished tasks it
continues, and the current sub-state (`awaiting-participant`, `degraded`, …). A client sets `mode`
on the first message to keep a task in `input-required` between turns, and `transition: "complete"`
on a message to close a long-running one. A failed task's status message carries `error: { kind,
message }` here.

## Activation

Send `A2A-Extensions: https://madarauchiha-314.github.io/rusty-harness/a2a/ext/task/v1`
(several URIs comma-separated) on a request; the server applies the extensions it
advertises and echoes them in the response's `A2A-Extensions`. The metadata key is the
URI itself. Back to [all extensions](../).
